# Flux Dev Environment

This directory contains the GitOps desired state for the dev AKS cluster.

Flux watches this path and continuously reconciles the cluster so that the live Kubernetes state matches what is declared in Git.

## Directory Structure

~~~text
clusters/dev/
├── flux-system/
│   ├── gotk-components.yaml
│   ├── gotk-sync.yaml
│   └── kustomization.yaml
├── apps/
│   ├── namespace.yaml
│   ├── helmrelease.yaml
│   └── kustomization.yaml
├── policies/
│   ├── networkpolicy.yaml
│   └── kustomization.yaml
└── kustomization.yaml
~~~

## What Each Folder Does

### flux-system/

Contains Flux bootstrap manifests generated by `flux bootstrap github`.

These files install and configure the Flux controllers and define how Flux syncs this repository.

Do not edit generated Flux component manifests manually unless intentionally upgrading or reconfiguring Flux.

### apps/

Contains application-level desired state.

In this project, the app is deployed through a Flux HelmRelease that references the Helm chart stored in this same repository under:

~~~text
charts/devsecops-api/
~~~

The HelmRelease defines:

- release name
- target namespace
- chart path
- image repository and tag
- app configuration values
- Key Vault CSI values
- Workload Identity annotations
- single-node AKS deployment strategy

### policies/

Contains Kubernetes security policies applied through GitOps.

Current policy:

~~~text
devsecops-api-allow-same-namespace
~~~

This NetworkPolicy limits inbound traffic to the app pods to traffic from the same namespace on TCP port 8000.

## GitOps Source Model

The Helm chart lives inside this repository, so Flux uses:

~~~text
GitRepository + HelmRelease
~~~

The project does not use a HelmRepository in v1 because the chart is not published to a separate Helm or OCI registry.

## Operational Rule

Git is the source of truth.

Application deployment changes should be made by updating files in this directory and committing them to `main`.

Manual `kubectl apply` is not the deployment mechanism for the application.

## Useful Commands

~~~powershell
flux get sources git -A
flux get kustomizations -A
flux get helmreleases -A
~~~

Force reconciliation:

~~~powershell
flux reconcile source git flux-system -n flux-system
flux reconcile kustomization flux-system -n flux-system
flux reconcile helmrelease devsecops-api -n devsecops-api --with-source
~~~

Check the live app:

~~~powershell
kubectl get pods -n devsecops-api -o wide
kubectl get deploy devsecops-api -n devsecops-api -o jsonpath="{.spec.template.spec.containers[0].image}{'\n'}"
kubectl get deploy devsecops-api -n devsecops-api -o jsonpath="{.spec.strategy.type}{'\n'}"
~~~
